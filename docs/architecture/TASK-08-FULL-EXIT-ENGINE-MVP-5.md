## Veles exit model

Veles provides three take-profit modes:

1. Simple / Простой — one limit TP by percentage from average position price.
2. Custom / Свой — multiple partial take-profit levels, optionally with break-even protection.
3. Signal / Сигнал — market exit generated by configured indicator/filter signal, with Minimum P&L.

Veles also has Stop Loss as a separate protective exit mechanism.

## 1. Fixed TP / Простой

The existing FixedPercentageTP must be preserved and brought into the common Exit Engine.

Rules:

- profit percentage is calculated from current average position price;
- LONG TP is above average price;
- SHORT TP is below average price;
- execution is a limit order;
- after every DCA/averaging fill:
  - cancel old TP;
  - recalculate average price;
  - create a new TP at the new average price;
  - TP volume equals the current remaining position volume.

This behavior is explicitly documented by Veles.

## 2. Multi-Take / Свой

Implement a sequence of partial exits.

Each take contains:

- offset_percent — profit level relative to current average position price;
- volume_percent — percentage of the current position to close at that take.

Rules:

- takes are ordered by increasing profit level;
- each take closes its configured portion;
- remaining position stays open;
- after DCA, the take grid is recalculated from the new average price;
- already executed takes remain immutable;
- only remaining takes are recalculated;
- total configured take volume must be valid;
- the final take may close the remaining position after rounding/lot constraints.

Use limit orders for normal Multi-Take exits, consistent with Veles.

Do not silently normalize invalid user configuration into another strategy. Validate it.

## 3. Signal TP / Сигнал

Signal TP closes the position with a market order when the configured Veles Filter/Signal generates an exit event.

Reuse the existing Filter/Signal engine from Task №5.

Do NOT create another indicator/condition system.

Support:

- Signal configuration;
- Long and Short;
- calculation timing already supported by the Strategy Engine;
- market execution;
- Minimum P&L.

The Signal TP must be an exit decision and must not submit broker orders directly.

## 4. Minimum P&L

Minimum P&L is a gate for Signal TP.

Signal TP can close only when:

1. configured signal fires;
2. current position P&L meets or exceeds the configured minimum.

The minimum is measured from the position's current average price using the project's P&L convention.

Do not confuse Minimum P&L with Stop Loss or Maximum Drawdown.

Minimum P&L applies to Signal TP only.

## 5. Break-Even Protection

Veles calls this "Стоп-лосс в безубыток", but it is NOT the ordinary loss-limiting Stop Loss.

It is available with Custom / Multi-Take and requires at least two takes.

After the first take executes:

- cancel the remaining DCA/Grid orders;
- activate a market protection stop for the remaining position.

Two reference modes:

### From average position price

Protection level:

average_price + deviation for LONG
average_price - deviation for SHORT

### From previous take-profit

Protection level:

previous_take_price + deviation for LONG
previous_take_price - deviation for SHORT

Deviation may be:

- positive;
- zero;
- negative.

After subsequent takes:

- if reference = average, protection remains based on average price;
- if reference = previous take, protection moves to the previous executed take level plus deviation.

Protection is a market exit.

It must not be confused with ordinary Stop Loss.

## 6. Simple Stop Loss

Implement percentage Stop Loss as a separate exit mechanism.

Veles behavior:

- it is a market exit;
- for a configured grid, the simple stop becomes active after the grid is fully assembled;
- its level is calculated relative to the configured grid/reference price according to Veles semantics;
- the resulting stop level must not be confused with Maximum Drawdown.

For the current engine, isolate the level calculation in a dedicated component so the Veles formula is explicit and testable.

Do not silently invent an alternative formula.

## 7. Signal Stop Loss

Implement indicator/filter based Stop Loss.

Conditions:

1. configured indicator/filter signal fires;
2. configured minimum offset condition is satisfied, unless disabled.

Minimum offset reference:

- average position price;
- last grid order.

Behavior:

- if reference = last grid order and minimum offset is enabled, signal stop becomes active only after the required grid state exists;
- if reference = average position price, the stop may activate before the full grid is assembled;
- positive offset is allowed and can therefore produce a profitable exit;
- signal stop is a market exit.

Reuse Task №5 Filters/Signals.

Simple Stop Loss and Signal Stop Loss operate independently. Whichever exit condition occurs first closes the position.

## 8. Interaction with DCA/Grid

Exit Engine must integrate with Task №7.

### Fixed TP

After each DCA:

- cancel old TP;
- recalculate TP from new average;
- recreate TP for remaining position.

### Multi-Take

After DCA:

- recalculate remaining take prices from new average;
- preserve already executed takes.

### Break-Even

After first take:

- cancel DCA/Grid orders;
- keep protection stop according to configured reference/deviation.

### Stop Loss

The stop must use the current configured reference and current grid/position state.

### Signal exits

Signal TP and Signal Stop use the current position state when evaluating Minimum P&L / minimum offset.

## 9. Exit priority and simultaneous conditions

Exit decisions must be deterministic.

Do not invent undocumented user-facing priority between different exit mechanisms.

Implement an internal ExitDecision model that records:

- exit type;
- reason;
- trigger price/time;
- requested quantity;
- execution type;
- originating configuration.

When multiple exit conditions are simultaneously true on a single backtest candle and OHLC data cannot establish the intrabar order, use a deterministic documented policy in the backtest engine and expose the selected reason in the result.

Do not use future data.
