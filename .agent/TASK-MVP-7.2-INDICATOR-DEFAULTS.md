## Зачем

В расчёте индикаторов (`backend/app/strategies/indicators.py`) есть скрытые запасные значения: `p or 20`, `p or 9`, `p or 14`, `params.get("fast", 12)` и т. д. Если параметра в конфиге нет (конфиг создан через API/JSON, старая версия стратегии), расчёт молча берёт число, которого пользователь не вводил. При ревью MVP-7.1 (B5) форма была сделана с обязательными параметрами, но запасные значения в расчёте остались.

Решение владельца (2026-10-07): **значения по умолчанию оставить, но сделать их явными** — вынести в схему как `default`, показывать предзаполненными в форме и сохранять в конфиг конкретным числом. Скрытых значений в расчёте быть не должно.

## Утверждённый контракт (владелец, 2026-10-07)

Ничего сверх I1–I5 не придумывать. Если чего-то не хватает, остановиться на границе, описать в REPORT и спросить.

### I1. Единая таблица значений по умолчанию
Один источник правды в backend (например, в `IndicatorParamDef` / `IndicatorDef` каталога). Значения — ровно те, что сейчас зашиты в расчёте (владелец подтвердил):

| Индикатор | Параметры по умолчанию | Источник |
|---|---|---|
| RSI | период 14 | **Veles** (`Veles Help Center — engineering reference.md`: «RSI default period is 14») |
| Bollinger | период 20, K 2 | **Veles** (help.veles.finance/ru/filters, BB: дефолт 20 и 2) |
| SMA | период 20 | выбор проекта |
| EMA | период 9 | выбор проекта |
| MACD | fast 12, slow 26, signal 9 | выбор проекта |
| ATR | период 14 | выбор проекта |
| CCI | период 20 | выбор проекта |
| Williams %R | период 14 | выбор проекта |
| CMO | период 14 | выбор проекта |
| MFI | период 14 | выбор проекта |
| Stochastic | период 14, k_smooth 3, d_smooth 3 | выбор проекта |
| ADX | период 14 | выбор проекта |

У каждого значения признак источника: `veles` или `project`. Перед реализацией **перепроверить по документации проекта и help.veles.finance**, не документирует ли Veles значения для остальных индикаторов; если документирует и значение отличается — не менять молча, описать в REPORT и спросить.

### I2. Каталог отдаёт значения
`GET /api/strategies/indicators` для периода и каждого параметра возвращает `default` и `default_source` (`veles` | `project`).

### I3. Форма предзаполняет
При выборе индикатора в форме стратегии поля периода/параметров предзаполняются значением из каталога (пользователь может изменить). Рядом с полем — пометка источника: «по умолчанию (Veles)» или «по умолчанию (выбор проекта)». Остальные правила формы (U4: интерфейс не придумывает значений, финансовые поля пустые) не меняются.

### I4. Расчёт без скрытых значений
Из `indicators.py` убрать все запасные значения (`or N`, `.get(..., N)`). Параметр отсутствует → понятная ошибка валидации (`POST /api/strategies`, `/validate`: 422 с указанием индикатора и параметра, по-русски в сообщении для UI) и ошибка в расчёте (бэктест/live) вместо молчаливой подстановки. Каталог: `required=True` для всех параметров, которые расчёт использует.

### I5. Существующие конфиги
Версии стратегий неизменяемы, миграцию данных **не делать**. Версия без обязательного параметра при бэктесте/старте бота даёт явную ошибку «укажите параметр…»; пользователь создаёт новую версию. Описать это поведение в REPORT.

## Ограничения (AGENTS.md)

- Семантика Veles, контракты D/C/S/N/L/E/R/U не меняются; формулы индикаторов не меняются.
- Значения `project` — решение владельца, не документация Veles; не выдавать их за Veles (ни в UI, ни в коде, ни в REPORT).
- Вне задачи: новые индикаторы, изменение формул, диапазоны допустимых значений сверх уже существующих проверок.

## Тесты

- Каталог: для каждого индикатора есть `default` и `default_source` по таблице I1; набор ключей каталога и расчёта совпадает (существующий тест).
- Расчёт: для каждого индикатора отсутствие параметра → ошибка (не подстановка); явное значение → то же число, что раньше (регрессия: результаты индикаторов с параметрами из таблицы не изменились).
- API: стратегия без обязательного параметра → 422.
- Фронтенд (vitest + jsdom): при выборе индикатора поля предзаполнены из каталога, пометка источника видна; пустое значение блокирует отправку.
