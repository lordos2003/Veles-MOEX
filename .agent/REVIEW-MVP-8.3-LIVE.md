## Найденный дефект

### D3 (блокер). CSP-ошибка в консоли при открытии любого модального окна

- **Воспроизведение:** статический сервер с теми же заголовками, что `docker/nginx.conf` (`Content-Security-Policy: default-src 'self'; frame-ancestors 'none'; connect-src 'self'`). Загрузка страниц, календарь, пресеты, список бумаг — чисто. Но **открытие диалога** («Закрыть песочничный счёт?») и **мобильного меню** → в консоли: `Refused to apply inline style because it violates the following Content Security Policy directive: "default-src 'self'"` (по одной записи на открытие; обе темы).
- **Причина:** Radix `Dialog.Overlay` оборачивается в `react-remove-scroll`, который через `react-style-singleton` создаёт элемент `<style>` (блокировка прокрутки и компенсация полосы прокрутки). Inline `<style>` под CSP без `style-src 'unsafe-inline'`/nonce блокируется: ошибка в консоли и **блокировка прокрутки страницы не применяется** (под открытым окном страница прокручивается).
- **Почему не заметили:** в раунде 1 я прогонял axe с `bypass_csp`, а CSP-проверка не открывала модальные окна — это мой пропуск (дефект в коде раунда 1). Кодер этот сценарий в L1 проверить не мог (панель Console в встроенном браузере недоступна) и записал L1 как «ОК» — для открытых модальных окон это неверно.
- **Почему блокер:** в задании владельца явный критерий «консоль без CSP-ошибок»; ошибка воспроизводится на каждом открытии диалога/меню.
- **Что нельзя делать:** ослаблять CSP в `docker/nginx.conf` (`'unsafe-inline'` для стилей) — CSP принят как контракт безопасности MVP-8.0 (G2); менять его можно только отдельным решением владельца.

## Замечания к отчёту

1. L1: «ОК» не подтверждена для состояний «открыт диалог / меню» (см. D3). Для проверки CSP без панели Console можно подписаться на событие `securitypolicyviolation` (`document.addEventListener('securitypolicyviolation', …)` через `evaluate` до открытия окна) и сообщить счётчик.
