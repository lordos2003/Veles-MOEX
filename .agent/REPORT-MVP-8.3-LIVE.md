## Найденные дефекты (L9) и фиксы

### Дефект 1. ConfirmDialog не возвращал фокус на элемент, открывший диалог

- **Проявление:** после закрытия диалога (Esc или «Отмена») `document.activeElement` = `body` вместо кнопки, открывшей диалог.
- **Причина (по исходникам `@radix-ui/react-dialog@1.2.0`):** `DialogContentModal` в собственном `onCloseAutoFocus` **всегда** вызывает `event.preventDefault()` и фокусит `context.triggerRef.current`. `triggerRef` заполняется только компонентом `DialogTrigger`; ConfirmDialog — управляемый (`open` prop, без `DialogTrigger`), поэтому `triggerRef` пуст: ни вернуть фокус самому (null), ни отдать событие `FocusScope` (его дефолт вернул бы `previouslyFocusedElement` — элемент в фокусе на момент открытия) — фокус остаётся на body.
- **Фикс** (`frontend/src/components/ui/Dialog.tsx`, функция `DialogContent`): в `onOpenAutoFocus` (вызывается Radix **до** переноса фокуса внутрь) запоминаем `document.activeElement`; в `onCloseAutoFocus` — `event.preventDefault()` + `lastFocused.current?.focus()`. Работает и для управляемого ConfirmDialog, и для SheetContent (мобильное меню), т.к. не зависит от `triggerRef`.
- **Тест** (`frontend/src/components/ui/ui.test.tsx`): закрытие по Esc возвращает фокус на триггер (Harness с `useState`).
- **Проверка в живом браузере (после пересборки из `1e3b443`), диалог «Закрыть песочничный счёт?»:**
  - после Esc: `activeElement` = BUTTON «Закрыть песочничный счёт», диалог закрыт;
  - после «Отмена» (мышь): `activeElement` = BUTTON «Закрыть песочничный счёт», диалог закрыт.

### Дефект 2. Tab из открытого списка InstrumentPicker уводил фокус на body

- **Проявление:** при открытом списке (фокус на `input[role=combobox]`) нажатие Tab переводило фокус на `body` вместо следующего поля («Метод расчёта»). С закрытым списком Tab работал корректно. Воспроизводилось детерминированно (4/4).
- **Причина:** список (`<ul role="listbox">` в `InstrumentPicker`) удалялся из DOM после того, как браузер уже вычислил следующий фокусируемый элемент.
- **Фикс** (`frontend/src/components/InstrumentPicker.tsx`): в `onKeyDown` добавлена ветка `event.key === "Tab"` → `setOpen(false)` — список закрывается **до** перехода фокуса (обновление из keydown-обработчика React сбрасывается синхронно).
- **Тест** (`frontend/src/components/InstrumentPicker.test.tsx`): Tab закрывает список (aria-expanded=false, listbox отсутствует).
- **Проверка в живом браузере (форма «Новая стратегия»):**
  - до Tab: `aria-expanded=true`, listbox открыт (270 опций), фокус на поле «Ценная бумага»;
  - после Tab: listbox отсутствует, `aria-expanded=false`, `activeElement` = SELECT «Метод расчёта» (не body).

## Ограничения

- **L10**: IAB не предоставляет эмуляцию `prefers-reduced-motion` (нет панели Rendering DevTools) — прямая проверка в живом браузере не выполнялась; подтверждено аудитом кода, скомпилированного CSS и юнит-тестами R10.
- **L1**: панель DevTools Console в IAB недоступна как отдельный инструмент — проверка по сетевым записям (performance entries), загрузке ресурсов и отсутствию видимых ошибок/вспышки.
- **L4**: запуск/остановка бота в песочнице детально не воспроизводились — к моменту отчёта ботов на странице нет (созданные в рамках проверок удалены); списки и CRUD-операции проверены полностью.
- Скриншоты для L9 (возврат фокуса из диалога) не прикладывались отдельно: кадр диалога «Закрыть песочничный счёт?» содержал бы идентификатор счёта; результат подтверждён замерами `document.activeElement` (приведены выше) и юнит-тестом.
