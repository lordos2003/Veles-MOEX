## B1. Чекбокс — область ≥ 32 px (A4)

**Было (по ревью B1):** `CheckboxInput` — `input` 16×16 без обёртки `label` (Chrome не применяет padding к нативному чекбоксу, computed `padding: 0`); два чекбокса `StrategyFormPage` — внутри `label` 1044×20, то есть 20 px по высоте.

**Стало:**

- `FormControls.tsx` — `CheckboxInput` обёрнут в `<label className="flex min-h-8 min-w-8 cursor-pointer items-center justify-center">`; сам чекбокс — `h-4 w-4 accent-zinc-400` (визуальный размер 16 px не менялся), программная подпись (`aria-label` из `Field`) и видимые тексты без изменений.
- `StrategyFormPage.tsx` — `label` строки чекбокса сигнала: `flex cursor-pointer items-center gap-2 text-sm font-medium text-zinc-200` → `flex min-h-8 cursor-pointer items-center gap-2 text-sm font-medium text-zinc-200`.
- Тест: `FormControls.test.tsx`, `«A4 (раунд 2 B1): чекбокс обёрнут в label — кликабельная область 32×32»` — проверяет наличие `label` с `min-h-8`/`min-w-8` вокруг чекбокса.

**Живой замер (финальный бандл, `/strategies/new`, `getBoundingClientRect`):**

| Чекбокс | Видимый input | Кликабельная область (label) |

| «Экстренная остановка» | 16×16 px | 527×**32** px |

Область нажатия — ≥ 32 px по высоте; визуальный размер самого чекбокса не менялся.

## B2 + U13. «Период»: календарь по датам, пресеты по значку

Ревью B2: Esc не закрывал календарь, открытый с клавиатуры (обработчик был только на текстовом поле и диалоге; кнопка «Открыть календарь» держала фокус). Замечание M1 — улучшение клавиатуры на самом поле.

**Решение — контракт U13 (закрывает и B2, и M1).** `PeriodPicker.tsx` переработан:

- **Поле** («Период», `readOnly`, `aria-label` «Период») — открывает календарь по клику, **Enter, Space и ArrowDown** (M1 закрыт: путь с клавиатуры начинается с самого поля).
- **Значок** (кнопка, `aria-label="Быстрый выбор периода"`) — открывает только панель пресетов (Месяц / 3 месяца / 6 месяцев / Год / 3 года / Весь период; «Весь период» без данных — disabled, как раньше).
- **Календарь** — только месяц/даты/время/подсказка; раздела «Быстрый выбор ▾» внутри календаря **больше нет** (надпись «Быстрый выбор» не встречается в DOM вообще).
- **Один попап за раз**: закрытие по `mousedown`/`focusin` вне области (слушатели на `document` для `[open, presetsOpen]`).
- **Esc** — на общем корневом элементе (`onRootKeyDown` + `onKeyDown` попапов): закрывает любой из попапов и **возвращает фокус** на элемент-открыватель (поле или значок). B2 закрыт: Esc работает независимо от того, чем открыт попап.
- Навигация в пресетах: ArrowDown/ArrowUp переводит фокус между кнопками, Enter — выбор (кнопки), Tab — по умолчанию.

**Тесты** (`PeriodPicker.test.tsx`, блок «U13 (раунд 2)», 8 новых сценариев): календарь без пресетов; пресеты без календаря; открыт только один попап; Esc из поля закрывает календарь и возвращает фокус; Esc из значка закрывает пресеты и возвращает фокус; текста «Быстрый выбор ▾» в документе нет; поле открывает календарь по Enter/Space/ArrowDown; ArrowDown/ArrowUp перемещают фокус по опциям пресетов.

**Адаптация существующих тестов — только то, что потребовал U13 (что было → что стало):**

- `BacktestPage.test.tsx`: 4× `getByLabelText("Открыть календарь")` → `getByLabelText("Период")` (календарь теперь открывается полем); 1× `getByText("Быстрый выбор ▾")` → `getByRole("button", { name: "Быстрый выбор периода" })`.
- `PeriodPicker.test.tsx`: 3× `getByText("Быстрый выбор ▾")` → клик по значку (`aria-label`); тест «Весь период» — календарь переоткрывается кликом по полю перед проверкой подсказки; комментарий disabled-опции обновлён.
- Проверки U11/U12 (пустой период, ISO-период, портфель данных) не ослаблены — см. `npm test`.

## B3. Placeholder ≥ 4.5:1

Ревью B3: в Tailwind 4 `::placeholder` по умолчанию — `color-mix(in oklab, currentcolor 50%, transparent)` (было gray-400 в v3); поля даты/времени `PeriodPicker` давали **4.42:1 < 4.5**.

**Исправление:** `frontend/src/index.css`, `@layer base`:

```css
::placeholder {
  color: var(--color-text-muted); /* #a1a1aa */
  opacity: 1;
}
```

Итог: 6.91:1 на surface (`#18181b`), 7.76:1 на page (`#09090b`) — выше 4.5:1 для всех полей (включая дату/время `PeriodPicker`), вид близок к v3.

**`check:contrast` расширен** (`frontend/scripts/check-contrast.mjs`): пары плейсхолдеров `«placeholder text-muted on bg-surface»` / `«placeholder text-muted on bg-page»` (источник — `index.css ::placeholder`). **25 пар текста/фона, 0 ниже 4.5:1** (было 24 — плейсхолдеры не проверялись).

**Живой замер:** computed `::placeholder` у поля «например, 100000» = `rgb(161, 161, 170)` (`#a1a1aa`), цвет самого текста поля — zinc-100.

## Правки отчёта раунда 1 (обязательные из ревью)

1. **A4** — исправлено: чекбокс визуально 16×16 при кликабельной области **≥ 32 px** (`label`-обёртка; способ проверки — `getBoundingClientRect` + тест, см. B1).
2. **A6** — «дефектов не найдено» убрано: найденный дефект B2 и его закрытие описаны выше.
3. **T2** — добавлено изменение v4: `::placeholder` (color-mix 50 % currentcolor вместо gray-400) и его исправление в Части 2 (B3).
4. **«Часть 1 визуально 1:1»** — уточнено. На «Обзоре» колонки таблицы сместились на 2–9 px. **Причина установлена и воспроизведена при одинаковых данных и прокрутке:** в Tailwind 4 preflight добавлен универсальный сброс `*, :after, :before, ::backdrop { margin: 0; padding: 0 }` (в v3 его не было), что убирает UA-дефолт Chrome `th, td { padding: 1px }`. Подтверждение по вычисленным стилям: ячейки таблицы — v3 `padding: 4px 1px`, v4 `4px 0px`; классы ячеек (`py-1`) и содержимое идентичны; также `border-color` ячеек стал `oklch(...)` вместо `rgb(229,231,235)` (тот же визуальный цвет zinc-200 — тот же сброс). Замер при пересъёмке: колонки `x=98/509/696/925/1063` (мастер) → `98/518/704/934/1068` (Часть 1). Это допустимое следствие preflight v4 (данные, классы и сетка не менялись; ломающего сдвига нет) — перечислено здесь как известное отличие.
5. **`12-strategy-new-after1.png`** — переснят (и парный `02-strategy-new-before.png`) в **одинаковом состоянии**: страница сверху (`scrollY = 0`), форма пустая, инструменты загружены. Для честного сравнения заново сняты и `00-overview-before.png` / `10-overview-after1.png` (та же методика).
6. **Скриншоты U13** — `27b-period-closed.png` (поле закрыто), `28-period-calendar.png` (календарь: открыт кликом по полю с клавиатуры-пути), `29-period-presets.png` (пресеты: открыты значком) — **в одинаковом состоянии данных** на `/backtest` (период не выбран, «нет данных о доступном диапазоне»).
