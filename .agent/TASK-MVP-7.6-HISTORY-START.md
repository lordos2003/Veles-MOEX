## Зачем

В MVP-7.5 окно «Период» бэктеста сделано, но «Весь период» отключён и пресеты не фильтруются, потому что в API нет даты начала истории бумаги. Владелец решил (2026-10-08): брать её у T-Invest.

## Источник (официальный контракт T-Invest, `instruments.proto`)

Сообщения `Share` и `Instrument` содержат:
- `first_1min_candle_date` (поле 56) — «Дата первой минутной свечи»;
- `first_1day_candle_date` (поле 57) — «Дата первой дневной свечи».

Ничего другого про начало истории в документации нет. Бинарный поиск по `GetCandles` **не делать**.

## Контракт (владелец, 2026-10-08)

### H2. Хранение и синхронизация
- Миграция (одна голова): в `instruments` два поля `first_1min_candle_date`, `first_1day_candle_date` (timestamptz, nullable).
- Заполняются при «Синхронизировать инструменты» (адаптер читает поля из ответа T-Invest; типы T-Invest — только в адаптере). Нет значения у брокера → `NULL`, ничего не подставлять.
- Старые строки остаются `NULL` до следующей синхронизации.

### H3. API
- `GET /api/instruments` отдаёт оба поля (UTC, ISO). Другие контракты API не менять.

### H4. Какая дата для какого таймфрейма (проектное решение, утверждено владельцем 2026-10-08)
Документация называет только минутную и дневную даты. Применяем так:
- таймфреймы 1m, 5m, 15m, 30m, 1h, 4h → `first_1min_candle_date`;
- 1d, 1w, 1mo → `first_1day_candle_date`.
Если нужной даты нет (`NULL`) — «источника нет»: поведение как в MVP-7.5 («Весь период» отключён, пресеты не фильтруются, подсказка «нет данных о доступном диапазоне»). Пересчитывать и угадывать не нужно.

### U12. «Бэктест»
- Подсказка под полем: «Данные для бэктеста доступны с: ДД.ММ.ГГГГ» (дата зависит от выбранной бумаги и таймфрейма; меняются — подсказка обновляется).
- «Весь период»: от этой даты до текущего момента.
- Пресет виден, только если его начало не раньше этой даты (у молодой бумаги «Год»/«3 года» исчезают); дни календаря до этой даты неактивны.
- Компонент `PeriodPicker` уже принимает `earliestAvailable` (`YYYY-MM-DD`) — подключить; в UTC/локальное время не ошибиться (граница по дате в часовом поясе браузера, как формат отправки).
- Таймфрейм берётся из выбранной стратегии/формы бэктеста; не выбран — как «источника нет».

### F1. Хвост из MVP-7.5 (M1)
`lookback_bars: null` убрать из JSON-шаблона формы и из тела `POST /api/strategies` и `PUT` (если поле не задано пользователем, ключа нет). Явное значение в старых стратегиях сохраняется как есть.

## Тесты
1. Адаптер: маппинг двух полей на фейковом ответе (есть/нет значения).
2. Синхронизация сохраняет поля; повторная — обновляет; нет значения → `NULL`.
3. `GET /api/instruments` отдаёт поля.
4. Фронтенд: сопоставление таймфрейм → дата (H4); «Весь период» включён при известной дате и равен earliest → now; пресеты фильтруются; `NULL` → поведение MVP-7.5; подсказка меняется при смене бумаги/таймфрейма.
5. F1: форма не добавляет `lookback_bars`; JSON-режим его не показывает; старая стратегия с `lookback_bars` сохраняет значение.
