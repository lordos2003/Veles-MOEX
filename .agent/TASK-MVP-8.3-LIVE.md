# TASK-MVP-8.3-LIVE — Живой прогон интерфейса MVP-8.3 на Docker-стеке

## Статус

Назначен 2026-10-10 (Кодеру, по решению владельца). Контрольная ветка: `agent/control`.
Ветка: `agent/review/mvp-8.3-live` — **создавать только если найден дефект и нужен фикс** (от текущего `master`; SHA — `git ls-remote origin master`, сейчас `834016b`). Если дефектов нет — код не меняется, результат — только REPORT в `agent/control`.
Issue: #51. Основание: MVP-8.3 принят и опубликован (PR #49, merge `c8091c8`; ревью `.agent/REVIEW-MVP-8.3.md`). Независимое ревью шло на статической сборке с заглушками API и **не заменяет** прогон на настоящем backend и данных — это и есть цель задания.

## Зачем

Подтвердить на реальном стеке (backend + БД + nginx с CSP), что редизайн и выбор темы работают так же, как на заглушках: нет CSP-ошибок, шрифты грузятся, данные отображаются, сценарии проходят.

Новой семантики Veles нет. Код не менять без дефекта; поведение страниц, backend, `docker/`, `docker-compose.yml` не затрагивать.

## Подготовка

1. `git fetch origin` и `git checkout master` (в состоянии `834016b` или новее); прочитать `agent/control:.agent/REVIEW-MVP-8.3.md`.
2. Чистый запуск: `docker compose down -v && docker compose up -d --build` (exit 0). Зафиксировать `/api/health` → 200 и открытие интерфейса (`http://127.0.0.1:5173/`).
3. Токен T-Invest — только sandbox, только из локального `.env` (read-only граница не меняется). Токен/ключи **не** вставлять в REPORT, логи и скриншоты. Если токена нет — пункты L5–L6 выполнить на том, что доступно, и указать это в REPORT.

## Контракт

Для каждого пункта в REPORT — результат «ОК / дефект / не проверено» и скриншот (папка `.agent/screenshots/MVP-8.3-LIVE/`; без токенов и номеров счетов в кадре — при необходимости закрыть).

- L1. **Консоль/CSP.** Открыть DevTools → Console и Network до первой загрузки. На всех страницах, в обеих темах: ни одной CSP-ошибки и ошибки консоли; 4 woff2-шрифта загружены (200) с того же origin; внешних запросов нет; `theme-init.js` загружен (200), вспышки тёмного экрана при перезагрузке в «Светлой» нет.
- L2. **Обзор.** Данные T-Invest/счета/позиции/график свечей отображаются; выбор бумаги работает; прожектор на карточках не мешает (мышь).
- L3. **Бэктест.** Выбрать стратегию, версию, бумагу, период (календарь и значок пресетов), депозит → «Запустить бэктест» → результат отображается без ошибок. Повторить в «Светлой» теме.
- L4. **Боты → создать.** Список ботов; «+ Создать бота» — форма (стратегии, счета, бумаги грузятся); создать бота, затем изменить/удалить его; для запуска/остановки — только если счёт песочницы доступен.
- L5. **Стратегии.** Список, детальная страница, форма создания/редактирования: схема и индикаторы приходят с backend; сохранение новой версии работает.
- L6. **Песочница и счета.** Страница открывается; действия — только песочница (реальные деньги не трогать; значок режима не «Реальные деньги»).
- L7. **Тема.** Переключатель в шапке («Тёмная»/«Светлая») работает и сохраняется после перезагрузки и перехода по страницам; при светлой теме ОС и пустом `localStorage` — «Тёмная»; во второй вкладке тема подхватывается.
- L8. **Мобильная вёрстка.** Окно < 1024 px (DevTools, 360×740 и 768×1024): шапка без переключателя темы, мобильное меню открывается/закрывается (Esc, крестик, клик по ссылке), в меню есть блок «Тема оформления», переключение работает; горизонтального скролла нет ни на одной странице.
- L9. **Клавиатура.** Tab-проход по «Ботам» и форме стратегии: порядок логичен, фокус виден в обеих темах; переключатель темы — стрелки/Home/End; диалог подтверждения (закрытие песочничного счёта или удаление бота) закрывается Esc и возвращает фокус.
- L10. **Reduced motion.** Включить «уменьшить движение» в ОС/DevTools (Rendering → prefers-reduced-motion): анимации появления страниц и карточек отсутствуют, функциональность не страдает.
