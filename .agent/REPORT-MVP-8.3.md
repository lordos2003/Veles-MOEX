## Арт-направление («Ночной терминал»)

Холодные «чернильные» нейтрали (шкала zinc переопределена в `@theme`, поэтому старые классы получили новый вид без массовой правки разметки), один акцент — индиго (`accent` для заливки, `accent-bright` для фокуса/акцентного текста), три семантических цвета состояния (success/warning/error — отдельно от акцента, чтобы «подключено» и «выбрано» не путались). Тонкие границы, мягкая тень с верхним бликом, свечение акцента только у главных кнопок и выбранной карточки счёта, фоновое свечение страницы градиентом (без картинок).

Типографика: **Onest** (текст, кириллица) + **JetBrains Mono** (числа, цены, таблицы — `.num`, tabular-nums). Всего 2 семейства, 4 файла woff2 (только кириллица и латиница), self-hosted, `font-display: swap`, запасной шрифт с подгонкой размера (`size-adjust` 104% — коэффициент приближённый; CLS по Lighthouse 0.01–0.016).

Токены (`frontend/src/index.css`, `@theme`): цвет, радиусы (`control`, `card`), тени (`card`, `pop`, `glow`), motion (`--duration-fast/base/slow`, `--ease-out-expo`, `--ease-standard`), шрифты. Тема — только тёмная (`color-scheme: dark`).

### Выбранный эффект (R9) и обоснование
«Прожектор»: радиальный градиент и тонкая подсвеченная рамка следуют за курсором внутри карточки. Выбран, потому что он «дорогой», но не отвлекает от данных и не требует тяжёлых ресурсов. Реализация: JS только пишет `--mx/--my` (requestAnimationFrame, только для `pointerType=mouse`), всё рисует CSS (градиент + opacity). Включается лишь при `(hover: hover) and (pointer: fine) and (prefers-reduced-motion: no-preference)`; на таблицах с автообновлением («Боты») и формах не применяется. Проверено: при reduced-motion псевдоэлемент не создаётся (`content: none`), при обычном режиме на hover opacity = 1 (`states/spotlight-hover.png`).

## Ограничения и пробелы (честно)
1. **Живой прогон на Docker-стеке не выполнен**: в моей среде нет Docker-демона, а `127.0.0.1:5173` владельца из облака недоступен. Вместо этого — production-сборка, статический сервер с теми же заголовками, что у nginx (CSP, nosniff и т. д.), API-заглушки со **схемой стратегий и каталогом индикаторов из backend**. Остаётся владельцу (≈ 3 минуты): `docker compose down -v && docker compose up -d --build`, открыть интерфейс, пройти «Обзор» → «Бэктест» (запуск) → «Боты → создать» → мобильное меню (окно < 1024 px), убедиться, что в консоли браузера нет CSP-ошибок.
2. Проверка выполнена на Chromium; Safari/Firefox не проверялись.
3. Backtest реально запускался только на заглушке (`/api/backtests` возвращает фиктивный результат); логика не менялась.
4. Нативные `<select>` оставлены (кастомная стрелка потребовала бы `data:`-картинки, запрещённой CSP `default-src 'self'`).
5. Подгонка размера запасного шрифта — приближённая.
6. CI (`ci.yml`) не менялся: шаг `npm run lint` и `check:contrast` стоит добавить отдельным небольшим заданием (ESLint 10 требует Node ≥ 22.22.2; CI использует `22`, что соответствует).
7. `PROJECT_STATE.md` и приёмка — не трогались; PR в `master` не открывался (по заданию — после проверки владельцем).
8. Исполнитель = архитектор: рекомендую независимую проверку (например, Кодером по этому отчёту) либо личный просмотр владельцем.
