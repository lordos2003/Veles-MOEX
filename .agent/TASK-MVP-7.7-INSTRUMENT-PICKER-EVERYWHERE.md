## Зачем

В MVP-7.5 поиск бумаги (`InstrumentPicker`: тикер/название/FIGI, «Найдено: N из M», ↑↓/Enter/Esc) сделан для «Обзор → Рынок» и формы стратегии. На «Бэктест» и при создании бота остаются обычные выпадающие списки (`SelectInput`) — с 270 бумагами MOEX в них неудобно. Решение владельца (2026-10-09): «Бэктест → Инструмент» сделать как «Обзор → Рынок», и **везде, где выбирается бумага, использовать этот же механизм**.

## Контракт (владелец, 2026-10-09)

### P1. Места замены
- `BacktestPage.tsx` — поле «Инструмент» (`SelectInput` → `InstrumentPicker`).
- `BotsPage.tsx` — форма создания бота, поле «Инструмент (локальный)» (`SelectInput` → `InstrumentPicker`).
- **Аудит:** найти все остальные места выбора бумаги во фронтенде (в т.ч. инлайн-конфигурация бэктеста, «Песочница и счета», фильтры списков) и заменить так же. Если мест больше названных — перечислить в REPORT; если выбор бумаги где-то намеренно другой — написать почему.
- Используется **тот же компонент** `InstrumentPicker` (не копия); новых зависимостей нет.

### P2. Подписи и поведение
- Подпись поля везде «Ценная бумага» (термин MVP-7.5 U9); «Инструмент (локальный)» и «Инструмент» в местах выбора заменить. Отображение уже выбранной бумаги в списках (например, «Инструмент: SBER …» в карточке бота) — не менять.
- Значения по умолчанию нет (поле пустое, обязательное, как сейчас). Сохраняемое значение не меняется: локальный `instrument_id` (число) — контракты API не меняются.
- Picker работает по FIGI (как сейчас) → компонент переводит в локальный id там, где страница хранит `instrumentId`. Бумага без локального id (`id === null`) в списке выбора не показывается (как сейчас на «Боты»).
- «Бэктест»: смена бумаги по-прежнему пересчитывает подсказку «Данные для бэктеста доступны с…» и пресеты периода (MVP-7.6); ошибка «Выберите инструмент.» → «Выберите ценную бумагу.», привязана к полю.
- Если список инструментов не загрузился — «Инструменты не загружены.» (как в форме стратегии).

## Тесты
1. `BacktestPage`: поиск по тикеру/названию выбирает бумагу, в запрос `/api/backtests` уходит нужный `instrument_id`; подсказка «доступны с» меняется при выборе; пустой выбор → ошибка у поля, запрос не уходит.
2. `BotsPage` (создание): поиск → выбор → в `POST /api/bots` нужный `instrument_id`; без выбора кнопка «Создать» неактивна.
3. Каждое найденное аудитом место — минимум один тест выбора.
4. Существующие тесты не ослаблять; если правятся из-за смены селекта на combobox — перечислить в REPORT.
