## U10. «История, баров» убирается из формы, глубина считается автоматически (решение владельца 2026-10-08)

Факты: `lookback_bars` — проектное поле (`StrategyConfig.lookback_bars`), в Veles его нет. «Период» в Veles — диапазон дат бэктеста, это не оно. Сейчас без поля живой цикл не стартует (`LookbackNotConfigured`); документация Veles формулы глубины не задаёт (`market_context.py`). Рекурсивные индикаторы (EMA, MACD, RSI, ATR) зависят от всей истории, поэтому глубина влияет на их значения.

Требуется:
- убрать поле из формы и из JSON-шаблона формы; в схеме `lookback_bars` остаётся необязательным (старые стратегии с ним продолжают работать, явное значение приоритетнее расчётного);
- если поля нет — глубина считается движком по формуле H1 (ниже); `LookbackNotConfigured` больше не блокирует цикл при наличии расчёта;
- `SEGMENT_LABELS`/подсказки обновить; бэктест не менять.
- Тесты: расчёт по формуле H1 на наборе индикаторов (SMA — `период`, EMA/RSI/ATR/MACD — `5×период`, свечи со сдвигом, несколько условий — максимум), явное значение приоритетнее, стратегия без индикаторов.

### Решение владельца (2026-10-08): формула — вариант B (контракт H1)
Глубина истории, баров: `N = max_i(W_i + shift_i) + 1`, максимум по всем индикаторам и свечам в условиях входа и выхода (включая фильтры), где:
- `W_i = 5 × period_i` для рекурсивных индикаторов: EMA, MACD (берётся наибольший из периодов fast/slow/signal), RSI, ATR;
- `W_i = period_i` для остальных индикаторов с периодом (SMA, Bollinger, CCI, Williams %R, CMO и др.);
- свеча без периода: `W_i = 1`;
- `shift_i` — сдвиг (в барах) данного аргумента, `+1` — формирующаяся свеча.
- Если в стратегии нет ни одного аргумента, `N = 1`.
Кодер **не меняет** эту формулу и не вводит верхних/нижних ограничений; если `N` превышает глубину поиска снимка (`snapshot_search_factor`, `core/config.py`), цикл завершается существующей ошибкой нехватки истории — описать в REPORT, поведение не менять. Явное `lookback_bars` в конфиге приоритетнее расчётного.

## U11. «Бэктест»: поля «С / По» → выбор периода как в Veles (решение владельца 2026-10-08)

Сейчас (`BacktestPage.tsx`): два текстовых поля «С» и «По» с подсказкой «например, 2026-01-01T10:00». Нужно повторить «Период» из окна «Запустить бэктест» в Veles (скриншоты владельца):

1. **Одно поле «Период»** со значением вида `17.03.26 7:21 - 08.10.26 16:19` (начало – конец, формат ДД.ММ.ГГ Ч:ММ), стрелка раскрытия и справа кнопка-календарь.
2. **Клик по полю или по кнопке-календарю** открывает выпадающую панель:
   - календарь одного месяца: заголовок «март 2026», стрелки ← → для смены месяца, дни недели П В С Ч П С В (неделя с понедельника);
   - выбор диапазона кликами «начало → конец»: начало выделено сильнее, дни между — подсвечены; дни вне доступного диапазона неактивны (серые);
   - под календарём две строки ввода: начало и конец — поле даты `ДД.ММ.ГГГГ` и поле времени `ЧЧ:ММ` (с иконками календаря и часов), правка вручную синхронна с календарём.
3. **Быстрые периоды** (выпадающий список по стрелке/кнопке), справа у каждого показан диапазон `ДД.ММ.ГГ-ДД.ММ.ГГ`. Полный набор: «Месяц», «3 месяца», «6 месяцев», «Год», «3 года», «Весь период». **Показываются только те, что укладываются в доступную историю бумаги:** пресет виден, если его начало не раньше даты «данные доступны с». У молодой бумаги списка «Год»/«3 года» нет; «Весь период» есть всегда (если дата известна). Конец = текущий момент; начало: «Месяц» = −1 календарный месяц, «3 месяца» = −3, «6 месяцев» = −6 (в Veles: 08.09.26 / 08.07.26 / 08.04.26 при конце 08.10.26); «Год» = −365 дней (08.10.25), «3 года» = −1095 дней (09.10.23 в Veles); «Весь период» = от самой ранней доступной даты (в Veles 25.03.20) до текущего момента.
4. **Подсказка** под полем «Данные для бэктеста доступны с: ДД.ММ.ГГГГ» (как в Veles).

Ограничения, чтобы не придумывать семантику:
- Значение по умолчанию не подставлять (MVP-7.1, U4): поле пустое, пока владелец не выбрал период или пресет. Пресет — действие пользователя, а не значение по умолчанию.
- Часовой пояс и формат отправки не менять: как сейчас (`new Date(...).toISOString()` из локального времени браузера); `from`/`to` в API остаются теми же.
- Валидация: «Укажите период.»/существующие сообщения; новых правил не изобретать (начало позже конца — запрещено только если это уже проверяется; иначе ошибка из бэкенда).
- **Дата «доступны с»:** если в API уже есть источник самой ранней свечи/данных по выбранному инструменту и таймфрейму — использовать его; если нет — **не придумывать**: «Весь период» и подсказка отключены с пояснением «нет данных о доступном диапазоне», вопрос описать в REPORT для решения владельца (нужен ли новый эндпоинт). Дни до/после доступного диапазона блокировать только при наличии этого источника.
- Календарь — без новых тяжёлых зависимостей (допустима небольшая библиотека без транзитивных, либо свой компонент; выбор описать в REPORT). Весь интерфейс на русском; управление с клавиатуры (Esc закрывает панель, Tab по полям).
- Компонент общий (`components/PeriodPicker.tsx`), чтобы переиспользовать в других местах.
- Тесты vitest: выбор диапазона кликами, ручной ввод даты/времени, пресеты (с замороженным «сейчас»; «Год»/«3 года» скрыты у бумаги с короткой историей), закрытие по Esc, отправка корректных `from`/`to`, пустое значение → ошибка поля.
