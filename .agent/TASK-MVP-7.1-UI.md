## Утверждённый контракт (владелец, 2026-10-05)

Ничего сверх U1–U8 не придумывать. Если чего-то не хватает, остановиться на границе, описать в REPORT и спросить.

**Главное правило формы:** интерфейс **не придумывает значений**. Поле получает значение только (а) введённое пользователем или (б) значение по умолчанию, которое уже есть в JSON Schema `StrategyConfig` (`GET /api/strategies/schema`). Поле без значения по умолчанию остаётся пустым и обязательным, если оно обязательно в схеме. Никаких «удобных» предзаполнений (периодов индикаторов, процентов TP/SL, депозита, комиссий, сумм пополнения).

### U1. Каркас приложения

- Разделы: **Обзор** (то, что есть сейчас: статус T-Invest, счета, позиции, график), **Стратегии**, **Боты**, **Бэктест**, **Песочница и счета**. Допускается `react-router-dom`; другие тяжёлые зависимости — только с обоснованием в REPORT.
- Весь интерфейс по-русски. Термины — из справки Veles (`Veles Help Center — engineering reference.md`, `docs/architecture/*`). Таблицу «поле конфигурации → подпись в интерфейсе → источник термина» привести в REPORT; где термина в Veles нет — пометить «перевод проекта».
- Ошибки API показываются **дословно** (`detail` ответа 4xx/5xx), без замены на общее «что-то пошло не так».

### U2. Индикатор режима (безопасность)

- Новый эндпоинт `GET /api/runtime` (только чтение): `{sandbox: bool, live_trading_enabled: bool, tinvest_configured: bool}` из настроек приложения.
- На всех страницах виден режим: «Песочница» или «Боевой счёт». Боевой счёт + живая торговля включена → постоянная красная плашка «Реальные деньги».
- START бота в боевом режиме — только после окна подтверждения с явным текстом (счёт, инструмент, депозит).

### U3. Каталог индикаторов (backend)

`IndicatorSpec.name` — свободная строка, `params` — словарь, поэтому JSON Schema не даёт форме список индикаторов и их параметров. Нужно:

- `GET /api/strategies/indicators` — список индикаторов, которые **реально** поддерживает расчёт (`app/strategies/indicators.py` / `indicator_series`): имя, выходные серии (`series`), параметры (имя, тип, обязателен ли), какие поля `IndicatorSpec` используются (`period`, `method`, `params`).
- Значения по умолчанию в каталог **не выносить**, даже если они есть в сигнатурах Python-функций (например `rsi(period=14)`): документированного Veles значения по умолчанию для формы нет, AGENTS.md §2.
- Тест-сверка: каждая запись каталога вычисляется через `indicator_series` на фейковых свечах; каждое имя, которое понимает `indicator_series`, есть в каталоге. Каталог и расчёт не могут разойтись.

### U4. Стратегии — полная форма

- Список стратегий (название, последняя версия, дата) → карточка стратегии: история версий, просмотр любой версии (только чтение), «Изменить» → форма → сохранение создаёт **новую версию** (`PUT`), старые не меняются.
- Форма разделена на блоки, как в Veles:
  1. **Основное**: название, направление, таймфрейм, `lookback_bars`.
  2. **Условия входа**: метод расчёта; группы фильтров (между группами — ИЛИ, внутри — И); условие = аргумент 1, оператор, аргумент 2; аргумент — константа / индикатор (из каталога U3, с его параметрами, таймфреймом и сдвигом) / свеча (серия, таймфрейм, сдвиг). Добавление/удаление групп и условий.
  3. **Ордера (сетка)**: режим «Простой» / «Свой» / «Сигнал»; поля показываются по режиму (для «Своего» — таблица уровней; для «Сигнала» — группы сигналов тем же редактором фильтров).
  4. **Тейк-профит**: вид из схемы (`fixed_percentage`, `multi_take`, `signal`, `trailing`) с полями своего вида.
  5. **Стоп-лосс**: простой (процент + `stop_bot_after` — переключатель «да / нет» **без выбранного значения по умолчанию**) и сигнальный.
  6. **Риск**: поля `RiskConfig`.
- Подсказки к полям — из `description` схемы и терминов Veles. Для процента стопа — по E1: «процент сверх перекрытия сетки от цены первого ордера».
- Проверка: перед сохранением `POST /api/strategies/validate`; ошибки показываются **у соответствующих полей** (путь из ответа 422); результат проверки живой торговли (D1/E4) — отдельной плашкой: «Для живой торговли подходит» / «Только бэктест: <причина>».
- Переключатель «JSON»: просмотр и правка той же конфигурации текстом; изменения в JSON и в форме синхронны; невалидный JSON не сохраняется.
- Форма строится по JSON Schema + каталогу U3; новые поля схемы, которые форма не знает, показываются в общем виде (по типу из схемы), а не теряются при сохранении.

### U5. Боты

- Список: название, статус (цветом), инструмент, депозит, стратегия и версия, ошибки (`deal_error`, `last_error`), `last_skip_reason`, `stop_reason`.
- Создание: стратегия → версия, счёт (только сохранённые локально, с кнопкой «синхронизировать»), инструмент (поиск по тикеру/названию из `/api/instruments`), депозит (пустое поле).
- Действия: старт, стоп, экстренная остановка (с подтверждением), изменить депозит, сменить версию стратегии, удалить (с подтверждением). Что запрещено по правилам R5 — кнопка неактивна с подсказкой почему; ответ 409 всё равно показывается дословно.
- Страница бота: текущая сделка (`GET /api/bots/{id}/deal`) — статус, направление, P0, средняя цена, позиция, таблица уровней (цена, объём, статус, исполнено), TP (цена, объём), стоп (цена, объём, активен ли); история сделок с причиной закрытия (`take_profit` / `stop_loss` — по-русски).
- Обновление данных опросом. Интервал — настройка фронтенда (ops-параметр), по умолчанию 5 с; описать в REPORT.

### U6. Бэктест

- Ввод: стратегия и версия **или** текущая (несохранённая) конфигурация из формы; инструмент; таймфрейм (если задан в стратегии — подставляется и не меняется, B3 из MVP-7.0); период; депозит, комиссии maker/taker, проскальзывание — **пустые обязательные** поля.
- Результат: сводка (начальный и конечный капитал, чистый результат, ROI, сделки, win rate, макс. просадка, комиссии); таблица сделок (вход/выход, цены, объём, результат, причина); график свечей за период с отметками входов и выходов (существующий `CandleChart`, свечи — существующим эндпоинтом).
- Ошибки 422 (предел свечей, таймфрейм, нет лота/шага цены) показываются дословно рядом с формой.

### U7. Песочница и счета

- Статус T-Invest и режим (U2). Счета брокера с признаком «сохранён», кнопка «Синхронизировать счета»; кнопка «Синхронизировать инструменты».
- Песочница (только когда `sandbox=true`; иначе блок скрыт с пояснением): открыть счёт; пополнить (сумма и валюта — пустые обязательные поля); закрыть (с подтверждением).
- Предупреждение рядом с песочницей (факты из MVP-7.0): стоп-заявок в песочнице нет — бота со стоп-лоссом там не запустить; неисполненные заявки песочница удаляет после окончания торговой сессии.

### U8. Проверка в браузере

- Unit-тесты фронтенда на `vitest` (добавить в `package.json`, `npm test`):
  1. схема → начальное состояние формы: значения только из `default` схемы, обязательные поля без `default` пустые;
  2. форма → конфигурация → форма без потерь (включая незнакомые поля схемы);
  3. ошибки 422 с путями попадают к нужным полям;
  4. `stop_bot_after` не выбран по умолчанию; пустой выбор не превращается в `false`.
- Если есть возможность — e2e-прогон на Playwright против фейкового/моков API (создать стратегию → бота → открыть страницу бота; бэктест с ответом-моком) и скриншоты основных экранов в REPORT (`docs/screenshots/mvp-7.1/`). Если нет — так и написать.
