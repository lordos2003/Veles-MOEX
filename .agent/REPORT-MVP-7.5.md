## U10. Глубина истории по формуле H1 (вариант B)

### Форма/подписи

- Поле «История, баров» убрано из формы; в JSON-режиме (генерируется из формы)
  поля тоже нет. `lookback_bars` остаётся в «скрытых» полях
  (`StrategyFormPage.tsx` `handled`, комментарий U10), поэтому в
  «Дополнительных полях» не показывается, но старые стратегии с ним работают.
- `SEGMENT_LABELS`/`TERMS`: строки для `lookback_bars` удалены.

### Движок (`backend/app/trading/market_context.py`)

- `iter_filter_groups` сделан публичным (`app/strategies/config.py`) — обход
  всех групп условий (вход, сетки DCA, сигнальный тейк-профит/стоп-лосс).
- Контракт H1 реализован буквально (решение владельца 2026-10-08):
  `N = max_i(W_i + shift_i) + 1`, где
  - `W_i = 5 × period_i` для рекурсивных: **EMA, RSI, ATR**; для **MACD** —
    `5 × max(fast, slow, signal)`;
  - `W_i = period_i` для остальных индикаторов с периодом (SMA, Bollinger,
    CCI, Williams %R, CMO и др.) — в коде это ветка «не рекурсивный»;
  - свеча: `W_i = 1` (плюс `shift_i`);
  - без аргументов: `N = 1`;
  - `+1` — формирующаяся свеча.
- `computed_lookback_bars(config)` — расчёт по H1; `resolved_lookback_bars(config)`
  — явное `lookback_bars` приоритетнее расчётного.
- `LookbackNotConfigured` **сохранён** (импорты/тесты обратной совместимости),
  но **больше не выбрасывается** и не блокирует цикл; документация обновлена.
- `build_market_snapshot_context` и `_scheduler_snapshot`
  (`live_execution.py`) используют `resolved_lookback_bars`; `scheduler.py`
  (`_require_config`) проверяет только таймфрейм (S4), недостающий lookback
  цикл больше не останавливает. Бэктест не менялся.

### Поведение при нехватке истории (не менялось)

Глубина поиска снимка ограничена `snapshot_search_factor = 4` и
`snapshot_min_search_days = 14` (`app/core/config.py`). Если `N` по H1 превышает
доступную историю, цикл завершается **существующей** ошибкой нехватки истории —
ошибка, её текст и обработка не менялись (по требованию задачи). Верхних/нижних
ограничений на `N` кодер не вводил.

### Примечание к формуле

Формула H1 применяется в барах **таймфрейма бота** без конвертации периодов
аргументов (все аргументы стратегии — на таймфрейме бота; пересчёт «как в
младшем таймфрейме» не предусмотрен ни задачей, ни формулой). Если ревьюер/владелец
считает нужным другую трактовку — это изменение контракта H1, не поправка реализации.

Тесты: `backend/tests/test_mvp75_lookback.py` (10 шт.) — SMA=период (20→21);
EMA 9/RSI 14/ATR 14 = 5×период+1; MACD 12/26/9 → 5×26+1=131; свеча со
сдвигом (1+shift); несколько условий — максимум; shift добавляется к весу;
без аргументов → 1; явное `lookback_bars` приоритетнее (7 vs расчёт 49);
отсутствие поля → расчёт (RSI 14 → 71). Правки `test_mvp610_market_snapshot.py`
и `test_mvp613_scheduler.py` — под H1 (запрос снимка с расчётной глубиной;
вместо «ошибка при пропущенном lookback» — расчёт из аргументов).

## U11. «Бэктест»: один период, календарь, пресеты

### Реализация

Собственный компонент **`frontend/src/components/PeriodPicker.tsx`** — без новых
зависимостей (в проекте нет UI-библиотек календаря; задача допускала свой
компонент). Обоснование выбора: функциональность ограничена (один месяц,
диапазон, два инпута, пресеты), для стандартного календаря тянуть зависимость
не оправдано.

- **Поле «Период»**: read-only input со значением `ДД.ММ.ГГ Ч:ММ - ДД.ММ.ГГ Ч:ММ`
  (пример: `17.03.26 7:21 - 08.10.26 16:19`), справа кнопка-календарь «📅».
  Клик по полю или кнопке открывает панель. Пусто, пока период не выбран
  (значение по умолчанию не подставляется — MVP-7.1 U4; пресет — действие пользователя).
- **Панель**: календарь одного месяца; заголовок «март 2026»; ← → для смены
  месяца; дни недели П В С Ч П С В (неделя с понедельника). Диапазон — кликами
  «начало → конец» (первый клик — начало, второй — конец; повторный клик
  начинает новый диапазон). Начало выделено сильнее (`bg-sky-600`), конец —
  `bg-sky-500`, дни между — подсветка. Дни вне доступного диапазона неактивны
  (серые) — см. ограничение про источник «доступны с».
- **Ручной ввод**: две строки (С / По) — дата `ДД.ММ.ГГГГ` + время `ЧЧ:ММ`
  с иконками 📅/🕐; ввод синхронен с календарём (draft-состояние до полной
  пары дата+время; неполная пара не коммитится — новых правил валидации нет).
- **Пресеты** (кнопка «Быстрый выбор ▾»; справа у каждого диапазон
  `ДД.ММ.ГГ-ДД.ММ.ГГ`): «Месяц» (−1 календарный месяц), «3 месяца» (−3),
  «6 месяцев» (−6), «Год» (−365 дней), «3 года» (−1095 дней), «Весь период»
  (от самой ранней даты). Конец = текущий момент. Пресет виден, если его
  начало не раньше даты «данные доступны с» (при известной дате).
- **Клавиатура**: Esc закрывает панель (и список пресетов), поля панели
  доступны по Tab.
- **Подсказка** под полем: «Данные для бэктеста доступны с: ДД.ММ.ГГГГ».
- `BacktestPage.tsx`: поля «С»/«По» заменены одним полем «Период»
  (`PeriodPicker`), состояние `from`/`to` — `Date | null`; валидация пустого
  значения — «Укажите период.» (существующее сообщение заменено на одно для
  поля); **часовой пояс и формат отправки не менялись** —
  `new Date(...).toISOString()` из локального времени браузера; payload
  `/api/backtests` и параметры графика (`from`/`to` в камере) — те же.

### Ограничение: источника «данные доступны с» в API нет (вопрос владельцу)

В API нет ни одного эндпоинта с самой ранней свечой/данными по инструменту
(проверены: `/api/instruments?active=true` — только инструменты; эндпоинтов
истории по инструменту+таймфрейму нет). По требованию задачи источник не
изобретался. Реализовано:

- подсказка под полем: «нет данных о доступном диапазоне»; рядом с
  «Весь период» — пояснение «нет данных о доступном диапазоне», пресет
  отключён (disabled);
- блокировка дней **до** earliest не выполняется (нечего вычислить);
  заблокированы только дни после текущего момента (данных в будущем нет —
  это не новая семантика, а граница «доступного диапазона»);
- пресеты «Год»/«3 года» показываются (фильтр по истории не активируется без
  даты). **Фильтрация пресетов по истории и подсказка с датой заработают,
  когда появится источник** — компонент уже принимает `earliestAvailable`
  (формат `YYYY-MM-DD`).

**Вопрос для решения владельца:** нужен ли новый эндпоинт (самая ранняя
свеча/дата по инструменту и таймфрейму, например
`GET /api/market-data/{figi}/earliest?timeframe=...`)? Если да — это отдельная
задача; U11 готов к подключению.

Тесты (`PeriodPicker.test.tsx` — 8, `BacktestPage.test.tsx` — 2):
выбор диапазона кликами, смена месяца стрелками, ручной ввод даты/времени
(неполная пара не коммитится), Esc закрывает панель, пресеты с замороженным
«сейчас» (08.10.2026 16:19): «Месяц» = 08.09.26 16:19; «Год»/«3 года»
скрыты при истории с 01.06.2026; «Весь период» = earliest → now; без
источника «Весь период» отключён + пояснение; пустое значение → «Укажите
период.» и запрос не уходит; выбранный период уходит `from`/`to` ISO-строками.
