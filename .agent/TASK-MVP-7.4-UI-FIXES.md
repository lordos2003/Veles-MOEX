## Требования

### U1. Счета брокера: свободные деньги и капитал из портфеля
Симптом (скриншот владельца): после пополнения песочничного счёта карточка «Счета брокера» на «Обзоре» показывает «свободно: 0 · эквити: 0», в то время как «Позиции» показывают `RUB000UTSTOM 100000`. После перезагрузки страницы то же самое.
Причина: `GET /api/accounts` (`backend/app/api/tinvest.py`, `list_accounts`) строит ответ из `UsersService/GetAccounts`, который портфель не возвращает; деньги и капитал отдаёт `GetPortfolio` (его уже вызывает `GET /api/accounts/{id}` через `broker.get_account`).
Требуется: список счетов отдаёт для каждого счёта `available_cash`/`equity` из `GetPortfolio` (тот же расчёт, что в `get_account`; расчёт не менять). Ошибка портфеля по одному счёту (например, закрытый счёт) **не ломает весь список**: у такого счёта значения пустые/«—» с пометкой, остальные счета показываются. То же значение отображается на «Обзоре» и на странице «Песочница и счета» («Капитал»). Лишних вызовов брокера не плодить: запросы по счетам выполнять параллельно, ограниченно. Тесты: список с портфелем, с ошибкой одного счёта; фронтенд — отображение значений.

### U2. «Рынок»: живой поиск по загруженным инструментам
Вместо выпадающего списка — поле поиска с выпадающим списком совпадений. Поиск без учёта регистра по **любому вхождению** в тикер, название и FIGI (нечёткость и транслитерацию не добавлять). Показывать число найденных («Найдено: N из M»), состояние «ничего не найдено», выбор мышью и клавиатурой (↑ ↓ Enter, Esc). Выбранный инструмент сохраняется при обновлении данных (`load()`), как сейчас. Работает по уже загруженным активным инструментам (`/api/instruments?active=true`), запросов на каждый символ не делать. Тесты vitest: вхождение в середине тикера, по названию, по FIGI, регистр, пустой результат, выбор клавишей.

### U3. Подписи инструментов без «(тип / валюта)»
Сейчас: «ABIO — Артген (SHARE / rub)». Нужно: «ABIO — Артген». Убрать везде, где инструмент подписывается этой строкой (в первую очередь «Обзор → Рынок»; проверить стратегии, ботов, бэктест). Тип и валюту в карточке выбранного инструмента не убирать, если они там показываются отдельными полями.

### U4. Плашка успеха на «Обзоре»
«Синхронизировано инструментов: N» показывается красной (ошибочной) плашкой. Использовать `SuccessBanner` (MVP-7.3, P6); ошибки остаются красными.

### U5. Кнопка «Проверить» в форме стратегии
`frontend/src/pages/StrategyFormPage.tsx` шлёт `POST /api/strategies/validate` с телом `{"config": …}`, а эндпоинт принимает сам конфиг без обёртки: ответ всегда 422 «`body.exit: Field required`» (с MVP-7.1; найдено ревью MVP-7.3). Исправить на стороне UI (контракт API R4 не менять): слать конфиг без обёртки. Тест уровня страницы: валидная форма → «Проверить» → показан вердикт (`live_deal`), невалидная → ошибки у полей.

### U6. Сообщения 422 вне полей
Ошибки, которые не привязаны к полю формы (например, не выбран вид тейк-профита: `union_tag_not_found`), показываются сырым JSON-списком. Показывать читаемый русский текст: «поле: сообщение»; для известного случая «не выбран вид тейк-профита» — привязать сообщение к полю «Тейк-профит». Не изобретать новых правил валидации и не менять тексты, которые уже приходят с бэкенда (MVP-7.2).

### U7. Нижняя граница `pydantic-settings`
`backend/pyproject.toml`: `pydantic-settings>=2.3` → `>=2.7` (`NoDecode`, MVP-7.3 P3). `requirements.lock` не менять (там 2.15.0); сборка и тесты не должны измениться.

### U8. Синхронизация инструментов: защита от пустого ответа
Сейчас (MVP-7.3, P8) пустой список от брокера деактивирует все активные записи этого типа до следующей синхронизации (проверено ревью). Требуется: если после фильтра MOEX получилось 0 инструментов, ничего не деактивировать и вернуть понятную ошибку («справочник брокера пуст, записи не изменены»). Тест на оба случая (пустой ответ; ответ без единой MOEX-бумаги). Фильтр и деактивацию в остальном не менять.

## Критерий приёмки (живой прогон обязателен)

На **чистой копии без локальных файлов** (`git status` без `certs/` и `docker-compose.override.yml`), `docker compose down -v` → `up -d --build`:
1. «Песочница и счета»: открыть счёт, пополнить → «Капитал»/«свободно» показывают сумму сразу и после перезагрузки страницы; «Обзор → Счета брокера» тоже (U1).
2. «Обзор → Рынок»: ввести «сбер», «sber», часть названия, часть FIGI → список фильтруется; выбор клавишей; подписи без «(SHARE / rub)» (U2, U3).
3. «Синхронизировать инструменты» → зелёная плашка (U4).
4. Форма стратегии: «Проверить» на валидной форме показывает вердикт, на невалидной читаемые ошибки (U5, U6).
5. Тесты: полный `pytest`, `ruff`, `npm test`, `npm run build`, `alembic heads`.
