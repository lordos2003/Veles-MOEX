### Часть 2 — токены и доступность (отдельные коммиты)
- A0. Токены: в `@theme` объявить семантические токены (фон страницы, поверхность, граница, текст основной/вторичный/приглушённый, акцент, ошибка, предупреждение, успех) на базе **существующих** zinc-значений; новые классы использовать в общих компонентах (`InstrumentPicker`, `PeriodPicker`, кнопки/поля, шапка). Массовую замену во всех 6000 строк **не** делать — только общие компоненты и места, затронутые A1–A5.
- A1. Контраст: весь текст интерфейса ≥ **4.5:1** (WCAG AA) на своём фоне; `text-zinc-500/600` на тёмном фоне заменить токеном вторичного/приглушённого текста с достаточным контрастом. Результат — таблица «где было → где стало → отношение» в REPORT (посчитано формулой WCAG, не «на глаз»).
- A2. Подписи полей: каждый интерактивный элемент (input/select/textarea/button без текста/combobox) имеет программную подпись (`label htmlFor`, `aria-labelledby` или `aria-label`). Приоритет — «Бэктест» (7 из 17 без подписи), затем остальные страницы. Видимые тексты не менять.
- A3. Фокус: единый видимый индикатор `:focus-visible` для кнопок, ссылок, полей, элементов списка `InstrumentPicker` (через токен/базовый слой). Не убирать `outline` без замены.
- A4. Цели нажатия: интерактивные элементы высотой ≥ 32 px (мелкие иконочные кнопки — с `min-h`/padding); не ломать вёрстку таблиц и строк.
- A5. Фон и тема: `body` имеет явный фон и цвет текста из токенов; `color-scheme: dark` (интерфейс только тёмный); при светлой теме ОС не появляется белых подложек.
- A6. Клавиатура: `InstrumentPicker` и `PeriodPicker` управляются с клавиатуры (Tab/стрелки/Enter/Esc) — проверить; найденные дефекты исправить, если правка локальна, иначе описать в REPORT.

### U13. «Период»: календарь по датам, быстрый выбор — по значку (решение владельца)

Основание: решение владельца 2026-10-10 по внешнему виду оригинала Veles (поле «Период»: даты слева, значок календаря справа, отделённый разделителем). Документация Veles это поведение не описывает, поэтому контракт — решение владельца; ничего сверх перечисленного не добавлять (в частности, стрелку ▾ внутри поля из оригинала **не** вводить).

- **U13.1.** Клик по полю с датами (слева) открывает **календарь** (сетка месяца, поля даты/времени «с/по», как сейчас). Календарь содержит только это — без пресетов.
- **U13.2.** Клик по значку календаря (справа) открывает **только список пресетов** («Сегодня», «Неделя» и т. д. — те же пункты и логика `earliestAvailable`/«Весь период», что сейчас). Отдельная панель под значком, выровненная по правому краю поля; при открытом списке календарь закрыт, и наоборот (одновременно открыт один попап). Выбор пресета закрывает панель и подставляет период, как сейчас.
- **U13.3.** Надпись **«Быстрый выбор»** (и стрелка ▾ рядом с ней) удаляется из видимого интерфейса. Программное имя кнопки-значка (A2) — `aria-label="Быстрый выбор периода"`; значок остаётся значком календаря.
- **U13.4.** Клавиатура (закрывает B2 и M1 ревью): поле с датами открывает календарь по Enter/Space/↓; кнопка-значок открывает список пресетов по Enter/Space; **Esc закрывает любой открытый попап с любого элемента внутри компонента** (обработчик на корневом контейнере), фокус возвращается на элемент, открывший попап; внутри списка пресетов — ↓/↑/Enter; клик/фокус вне компонента закрывает попап (как сейчас).
- **U13.5.** Всё остальное в `PeriodPicker` без изменений: формат даты/времени, границы `earliestAvailable`, A1–A4 (контраст, подписи, фокус, цели ≥ 32 px).
- **Тесты.** Существующие тесты `PeriodPicker`/страниц, завязанные на прежнее поведение (кнопка «Быстрый выбор», календарь по значку), можно менять **только** под U13 и только в части этого поведения; каждое такое изменение перечислить в REPORT (что было → что стало). Остальные тесты не трогать и не ослаблять. Добавить тесты: клик по датам → календарь без пресетов; клик по значку → пресеты без календаря; Esc с кнопки-значка и с поля закрывает попап; нет текста «Быстрый выбор».
- **Скриншоты в REPORT:** поле закрыто; открыт календарь (клик по датам); открыты пресеты (клик по значку) — в одинаковом состоянии данных.
