## U1. Счета брокера: свободные деньги и капитал из портфеля

`backend/app/api/tinvest.py`, `list_accounts`:

- Список счетов по-прежнему строится из `GetAccounts` (имя, тип, валюта,
  id счёта), но для каждого счёта дополнительно запрашивается портфель
  через `broker.get_account(account_id)` — ровно тот же вызов и тот же
  расчёт, что в `GET /api/accounts/{id}` (`currency`, `available_cash`,
  `equity`); расчёт не менялся.
- **Решения по U1 (требование REPORT):**
  - *Способ:* портфельные запросы идут параллельно через
    `asyncio.gather` с общим `asyncio.Semaphore(5)` — ограниченное
    количество одновременных вызовов к брокеру, лишних запросов нет
    (ровно один `GetPortfolio` на счёт, как и раньше у детального
    маршрута).
  - *Толерантность:* ошибка портфеля по одному счёту (например, закрытый
    счёт — `AccountNotFoundError`, наследник `TInvestError`) перехватывается
    и не ломает весь список: счёт остаётся в ответе, но с
    `portfolio_available=false` и пустыми значениями; остальные счета
    показываются со своими значениями.
  - *UI:* «—» вместо суммы и пометка «портфель недоступен» на «Обзоре»
    (`OverviewPage.tsx`, строка счёта) и на «Песочница и счета»
    (`SandboxPage.tsx`, Баланс/Капитал).
- `backend/app/schemas/invest.py`: `AccountInfoResponse.portfolio_available:
  bool = True`; `frontend/src/types.ts`: `AccountInfo.portfolio_available?:
  boolean`.
- `_account_to_schema` получает `portfolio`/`portfolio_available`; подпись
  счёта берёт валюту и суммы из портфеля, а имя/тип — из `GetAccounts`.

Тесты: `backend/tests/test_mvp74_api.py` (2: список с портфелями; ошибка
одного счёта — остальные живы, у закрытого `portfolio_available=false`);
`backend/tests/test_mvp70_api.py` (фейковый `get_account` в stand-in);
`frontend/src/pages/OverviewPage.test.tsx` «U1: показывает свободно/эквити
из портфеля; у закрытого счёта „—“ и пометка».

Примечание к семантике: вместо пустых значений (`available_cash=0`)
используются «—» + пометка — это отображение, не новый источник данных.

## U6. Сообщения 422 вне полей

`frontend/src/api.ts`:

- `unwrapDetail`: если пришёл конверт `{"detail": ...}` (FastAPI-wrapped
  ошибка), он распаковывается; `ApiError.detail`/`message` и
  `verbatimMessage` работают с распакованным значением.
- `verbatimMessage` для массива ошибок: `loc` без `body` превращается в
  имя поля через `labelFor(paths.join("."))` (каталог русских подписей
  `frontend/src/lib/labels.ts`, MVP-7.2) — например
  `exit.take_profit` → «Тейк-профит». Итог: читаемое «поле: сообщение»
  вместо сырого JSON-списка. Для известного случая «не выбран вид
  тейк-профита» (`union_tag_not_found`) pydantic кладёт ошибку на тот же
  loc (`exit.take_profit`) — сообщение привязывается к полю «Тейк-профит»
  и в баннере, и у самого поля (`fieldErrors`). Тексты сообщений не
  менялись (они приходят с бэкенда, MVP-7.2 правило соблюдено).
- Сообщение без пути показывается без префикса.

Тесты: `frontend/src/lib/form.test.ts` (3 новых: распаковка конверта
`{ detail: [...] }`; русское имя поля; сообщение без пути) и
